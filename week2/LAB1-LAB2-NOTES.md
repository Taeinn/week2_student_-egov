# Week 2 · LAB 1–2 notes (e-Service กลาง เทศบาลนครตัวอย่าง)

## LAB 1 · สรุปโจทย์

**ระบบนี้คืออะไร** — e-Service กลางของเทศบาลสมมติ ประชาชนยื่นคำขอ 3 บริการ (SV-01 ขอสำเนาเอกสาร · SV-02 ฿500 คงที่ · SV-03 ขออนุญาตก่อสร้าง) แนบไฟล์ จ่ายผ่าน PromptPay QR จำลอง → เจ้าหน้าที่ตรวจ/ตีกลับ/ส่งต่อ → หัวหน้าอนุมัติ → ออกเอกสารดิจิทัล (ลายเซ็น HMAC) ตรวจได้ที่ `/verify` · ผู้บริหารดู Dashboard · ผู้ตรวจสอบดู Audit Trail · ThaiD / PromptPay / CA เป็นตัวจำลองทั้งหมด แล้วพิสูจน์ด้วย Playwright 51 TC

**บทบาท 6 บทบาท** (DECISIONS §1): `citizen` ประชาชน · `officer` เจ้าหน้าที่ (แผนก registry / works) · `head` หัวหน้าฝ่าย · `executive` ผู้บริหาร · `auditor` ผู้ตรวจสอบภายใน · `admin` ผู้ดูแลระบบ

**ทำไมต้องมี CONTRACT** — ทุกกลุ่มใช้ stack ต่างกันได้ แต่ TEST-PLAN กลางชุดเดียวต้องรันกับเว็บทุกกลุ่ม จึงต้องตกลง route · `data-testid` · ข้อความ error ตรงตัวอักษร · รูปแบบ API/JSON · test hook (`reset` `clock` `pay` `tamper`) ให้เหมือนกัน ถ้าไม่ตรง test กลางหา element ไม่เจอ หรือ assert ไม่ผ่านทั้งที่กฎถูก

### คำถามเช็กก่อนไปต่อ

1. **ขออนุญาตก่อสร้าง 101 ตร.ม.** → ฿1,000 + ฿10 × (101 − 100) = **฿1,010** (BR-05)
2. **ชำระ อ. 1 ธ.ค. 69 เวลา 16:30, SLA 3 วัน** → 16:30 ไม่ใช่ "ก่อน 16:30" จึงได้ D0 = พ. 2 ธ.ค. · นับวันทำการ 3 วันหลัง D0: พฤ. 3 · ศ. 4 · (ส.-อา. 5–6 และ จ. 7 ธ.ค. วันหยุดใน seed ไม่นับ) · อ. 8 → **อ. 8 ธ.ค. 2569 เวลา 16:30** (BR-12)
3. **ทำไม data-testid ต้องชื่อเดียวกัน** → Playwright 51 TC เป็นชุดกลางที่หา element ด้วย `data-testid` ตาม CONTRACT ถ้าแต่ละกลุ่มตั้งชื่อเอง test กลางจะใช้กับเว็บของกลุ่มไม่ได้ และเทียบผล/ล่าบั๊ก BUG_MODE ข้ามกลุ่มไม่ได้
